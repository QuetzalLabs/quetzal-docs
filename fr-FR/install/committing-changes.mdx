title: "Publication des modifications"
description: "Comment Quetzal publie les modifications dans ta base de code"
---

Quetzal publie les modifications dans ta base de code via le contrôle de version.

Le calendrier et la structure des modifications peuvent être configurés pour s'adapter au mieux au workflow de ton équipe.

## Qu'est-ce qui est publié ?

Nouvelles traductions, traductions

- Nouvelles traductions
- Révisions de traduction
- Mises à jour du code pour la couverture de localisation

Ces fonctionnalités peuvent être activées et désactivées dans les paramètres de ton intégration.

## Comment les modifications sont publiées

Les modifications sont intégrées à ta base de code via des commits Github.

Par défaut, les modifications sont publiées sur une seule branche via une seule pull request dédiée à la localisation.

Tu peux modifier ça pour publier plutôt par commits directs

## Branches actives

Par défaut, Quetzal ne surveille qu'une seule branche et y publie les modifications.

Tu peux ajouter de nouvelles branches à suivre en définissant un filtre pour les nouvelles branches à traiter, ou en invoquant Quetzal dans les commentaires d'une pull request.

Les branches peuvent aussi être ajoutées manuellement via le tableau de bord.

Les branches actives sont traitées et mises à jour par Quetzal en temps réel, garantissant que la localisation est à jour.


## Branche dédiée aux traductions

Tu as la possibilité de séparer les mises à jour de traduction des autres mises à jour de code.

Ça permettrait de fusionner automatiquement les modifications de traduction dans main, tout en laissant les autres modifications de code être publiées selon un modèle différent.

## Mises à jour manuelles

Si tu préfères mettre à jour ta base de code manuellement, tu peux plutôt récupérer les modifications via notre API.

Les modifications peuvent être consultées et intégrées à ton workflow à ta guise pour un contrôle maximal.
